Step1:
Running different Exploit from U-fuzz Engine
Make sure both the mutation and optimization was disabled

Select the potential exploit to run
$ sudo bin/ble_realtime_fuzzer --exploit=<Specific exploit from exploit list>

Normal Replication Tutorial

Step2:
Run single Emulation input

Script selection depends on exploit selection
$ ./run-input-zigbee.sh <target emulation input>
$ ./run-input-ble.sh <target emulation input> 
i.e., 
./run-input.sh target-zephyr/inputs/sm_pairing_rsp_good350.bin

GDB Replication Tutorial

Step2:
Run GDB Server Process with single Emulation input

Script selection depends on exploit selection
$ GDB=1 ./run-input-zigbee.sh <target emulation input>
$ GDB=1 ./run-input-ble.sh <target emulation input> 
i.e., 
GDB=1 ./run-input.sh target-zephyr/inputs/sm_pairing_rsp_good350.bin

Step3:
Attach the gdb server

$ gdb-multiarch <path to .elf> -ex "target remote localhost:1236" -ex "-enable-pretty-printing"
i.e.,
gdb-multiarch ./interval-500-fuzzed-clock-10t/zephyr.elf -ex "target remote localhost:1236" -ex "-enable-pretty-printing"

After the gdb client attached, can set break point for different exploit selected

bt *<addr>
